# AI Green Skills

> Green skills for different IA agents

Detection of impacting issues in existing code is right and mandatory... It is just not enough...

AI can help to detect such issue, but Eco-conception / Eco-design usually means designing and coding right from start, which means that ones who code and design must learn Green Skills to write better products.

Today, the code, and even the design, is more and more generated by AI. 
What can be code to make it generate more sustainable code, design, infra, or anything, is to give it some designed skills and agents.


## Architecture Principles

### Software development Livecycle

The eco-conception takes place all over the livecycle of software development

- conception
- specification
- UX Design
- Code
- Build
- Run

### SKILLS

To be efficient:

- as mentioned by Anthropic, SKILLS are not meant to be to big.
- they can include some code of documents to use

Sustainability Guidelines like W3C WSG, french RGESN, GR491, Afnor, or ISO ones are organised over themes which can be a first step to organise the skills, but the project is free to organise them differently when it make sense.

The idea is that the agents should only use the relevant skill depending of the context on which it is working: forms, modals, images, videos, ...

This same skills are meant to be usable by different kind of agents at different steps of the software development livecycle

### AGENTS

For a full software development livecycle integration, at start we will focus on 3 types of agents:

- **reader / crawler agents** : browse documents, pages, screens, ... using existing references, links, sitemaps
- **compliance control agents**: can focus on all or part browsed documents / pages, use the right skills at the right moments
- **genai agents**: 
  - business specification generation 
  - UX design system generation
  - code generation 
  - CI/CD generation 
  - audit reportss generation (ex: rgesn)
  - technical and business monitoring dashboard and alerting configuration generation
    - navigation issu detection (too many steps)
    - interrupted user worflow detection (badly designed feature UX)
    - recurrent support tickets detection on a theme (latency, usability, ...)
    - critics publish on social networks overwatch

### MCP SERVERS / CLI + SKILLS

#### Reuse Rule

Provided Agents & Skills réalisés should rewrite what already exist, they should be aware of specialized existing services which are already maintained by other organization

Example of existing Services: Figma, Sonarqube, Confluence, or ServiceNow MCP Servers

#### Distribution

The provided skills and agents should be made available through:

- An MCP Server interface
- A CLI + SKILL interface
- Project dependencies through https://github.com/vercel-labs/skills/blob/main/README.md
- IDE plugins/extensions 
- UX design solution (figma,sketch, …) plugins/extensions
